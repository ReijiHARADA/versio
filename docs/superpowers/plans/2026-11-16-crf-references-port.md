# CRF References Port Implementation Plan (stage 3a-1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port GROBID's `reference-segmenter` and `citation` CRF models to pure TypeScript and measure them with the field eval, without touching the production pipeline.

**Architecture:** A Wapiti model reader + Viterbi decoder over pruned models; GROBID tokenizer and feature generators ported from Java; lexicons as pruned assets. An eval adapter `crfport` feeds Versio's reference-section lines through segmenter → citation and maps labels to `FieldRecord.references`.

**Tech Stack:** TypeScript, vitest (node env), vite-node scripts, local GROBID 0.9.1 (dev only, `scripts/grobid-local.sh`) for parity.

**Spec:** `docs/superpowers/specs/2026-11-16-crf-references-port-design.md`

## Global Constraints

- No Java / GROBID / network in anything under `src/services/`. Local GROBID is used only by parity scripts.
- Do not change production behavior: nothing in `extractAcademicPdf` / `toPaper` / Resolver calls the new code in this plan.
- GROBID sources are Apache-2.0: every ported file starts with a header naming the GROBID source file and "ported from GROBID (Apache-2.0), modified". Do not port Wapiti C code; implement the model format from its file layout.
- Model/lexicon assets live in `src/services/pdfExtraction/crf/assets/` and are generated by a script from `~/.cache/versio-grobid/grobid-0.9.1/grobid-home` (not hand-edited). Total gzip size of assets ≤ 5 MB.
- Japanese papers: the adapter returns references unavailable for `language === "ja"`.
- Parity target: ≥ 95% token-label agreement with local GROBID for citation and reference-segmenter on the field-gold corpus.

## Review Focus

1. Unicode tokens (diacritics, CJK, ligatures `ﬁ`) — tokenizer must split exactly like GROBID's `TextUtilities`/`GrobidAnalyzer` default delimiters; test with `Müller`, `ﬁeld`, `「`.
2. Out-of-vocabulary observations — a pattern string absent from the pruned model contributes 0, never throws.
3. Very long reference sections (300+ refs) — Viterbi is O(T·L²); keep under 1 s for 300 refs.
4. References with DOIs / URLs — GROBID's identifier/url positions feature; `https://doi.org/10.x/y` must stay one token span.
5. Empty or missing reference section — adapter returns `[]` and does not mark the field unavailable.

### Task 1: Wapiti model reader and Viterbi

**Files:** Create `src/services/pdfExtraction/crf/wapiti.ts`; Test `src/test/pdfExtraction/crfWapiti.test.ts`

**Interfaces — Produces:**
- `export type CrfModel = { labels: string[]; patterns: Pattern[]; unigram: Map<string, Float64Array>; bigram: Map<string, Float64Array> }` (unigram arrays length L, bigram length L·L)
- `export function parseWapitiModel(text: string): CrfModel` — full Wapiti text format (`#mdl#`, `#rdr#`, patterns, `#qrk#` labels, `#qrk#` observations, sparse `index=hexfloat` weights). Observation offsets are assigned in quark order: `u` → L weights, `b` → L·L, `*` → L + L·L.
- `export function decode(model: CrfModel, rows: string[][]): string[]` — expand patterns per position (`%x[r,c]`, out-of-range → `_x-1`/`_x+1` style placeholders as Wapiti does), sum weights, Viterbi.

- [ ] Step 1: tests — synthetic 2-label model text: (a) parse counts labels/patterns, (b) hex floats `0x1.8p-1` = 0.75, (c) decode picks the label whose unigram weight dominates, (d) bigram weight flips a tie, (e) unknown observation contributes 0.
- [ ] Step 2: run, FAIL. Step 3: implement. Step 4: run, PASS.
- [ ] Step 5: commit `feat(crf): Wapiti model reader and Viterbi decoder`
